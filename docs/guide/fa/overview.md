# سیستم چطور به هم وصل است

EndpointAgents به کاربر ویندوز اجازه می‌دهد به‌جای تماس با پشتیبانی، مشکلش را در برنامهٔ Tray (به فارسی) بنویسد. یک عامل هوشمند کامپیوتر را بررسی می‌کند و در چارچوب فهرست‌های مجاز آن را تعمیر می‌کند. اگر نتوانست، یک کارشناس از همین داشبورد کار را به دست می‌گیرد.

## پنج بخش اصلی

| بخش | کجا اجرا می‌شود | چه کار می‌کند |
| --- | --- | --- |
| **Tray** | کامپیوتر کاربر، در نشست ویندوز خودش | پنجرهٔ گفتگو، وضعیت و کنترل، گزارش‌ها و کارت تأیید. وقتی پنجره بسته است، برای پاسخ تازه یا درخواست ری‌استارت یک پیام کوچک کنار ساعت نشان می‌دهد. فقط از راه فهرست ثابتی از عملیات ثبت‌شده به کامپیوتر دسترسی دارد. |
| **سرویس کامپیوتر (Endpoint service)** | کامپیوتر کاربر، با حساب LocalSystem | یک اتصال احراز‌هویت‌شده با کنترل‌پلین نگه می‌دارد، فرمان‌های مجاز را می‌گیرد و کنترل‌کنندهٔ مربوط را اجرا می‌کند. تنها named pipe که Tray با آن حرف می‌زند مال همین سرویس است. |
| **کنترل‌پلین (API)** | سرور، پورت 5052 | هویت، گفتگوها، رضایت کاربر، فهرست فرمان‌های مجاز و ثبت رویدادها با اوست. همه‌چیز را در SQLite نگه می‌دارد. |
| **Hermes** | سرور، فقط loopback (‏127.0.0.1:8642) | عامل هوشمند. گفتگو را می‌خواند، مهارت انتخاب می‌کند و ابزارهای کنترل‌پلین را صدا می‌زند. راه مستقیمی به هیچ کامپیوتری ندارد. |
| **داشبورد** | سرور، فقط loopback (‏127.0.0.1:3000) | میز کار پشتیبانی: گفتگوها، بسته‌ها، مهارت‌ها، توانایی‌ها، محیط و اپراتورها. |

## یک گفتگو، قدم به قدم

```text
User types in the Tray
  -> endpoint service (named pipe)
  -> control plane (authenticated SignalR, stored in SQLite)
  -> Hermes run  (masked prompt goes to the cloud LLM)
  -> Hermes calls a control-plane tool (MCP, loopback, run-scoped key)
  -> control plane checks the rules, then sends one allow-listed command
  -> endpoint service runs the fixed handler
  -> sanitised result goes back to Hermes, then a short Persian answer to the Tray
```

سه قاعده در همهٔ مراحل برقرار است:

1. **تصمیم با کنترل‌پلین است، نه هوش مصنوعی.** Hermes هرگز شناسهٔ دستگاه را نمی‌بیند. هر اجرا یک capability تصادفی می‌گیرد که سرور آن را به یک کامپیوتر و یک کاربر ویندوز وصل می‌کند. عامل نمی‌تواند به کامپیوتر دیگری دستور بدهد.
2. **فقط عملیات ثبت‌شده وجود دارد.** ابزاری نیست که دستور، اسکریپت یا فایلی را که هوش مصنوعی نوشته اجرا کند. عامل با شناسه یک کار یا یک بسته انتخاب می‌کند؛ کد یا فایل پشت آن را یک آدم بررسی کرده است.
3. **همه‌چیز ثبت می‌شود.** گفتگوها، فراخوانی ابزارها، اجرای کارها و تصمیم‌های رضایت ذخیره می‌شوند و در داشبورد دیده می‌شوند.

## عامل خودش چه کارهایی می‌کند

| نوع کار | نیاز به تأیید کاربر؟ |
| --- | --- |
| تشخیص فقط‌خواندنی (کارهای Look، اطلاعات سیستم) | خیر |
| تعمیر کوچک و برگشت‌پذیر (کارهای SafeFix) | خیر، ولی در ساعت محدود است و قبل و بعدش بررسی می‌شود |
| تعمیر فعال‌سازی ویندوز و آفیس | خیر، فقط با ابزارهای اختصاصی و بعد از بررسی‌های ایمنی |
| بستهٔ تعمیر بررسی‌شده (BAT یا EXE) که علائمش با مشکل کاربر بخواند | خیر، چون مدیر آن را بررسی و امضا کرده است |
| کارهای مزاحم (ری‌استارت دسکتاپ یا کامپیوتر، بستن برنامه) | بله، کاربر باید در گفتگو بگوید «بله» |
| هر چیز دیگر | عامل پیشنهاد می‌دهد و کاربر کارت را در Tray تأیید می‌کند |
