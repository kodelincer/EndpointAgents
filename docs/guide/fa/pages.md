# صفحه‌های داشبورد و عیب‌یابی

## هر صفحه برای چیست

| صفحه | آنجا چه می‌کنید | چه کسی |
| --- | --- | --- |
| **Overview** | وضعیت کنترل‌پلین، کامپیوترهای آنلاین و فعالیت‌های اخیر. مدیرها حالت تعمیرات (maintenance) را روشن یا خاموش می‌کنند. | همه می‌خوانند، مدیر تغییر می‌دهد |
| **Endpoints** | کامپیوترهای متصل. مدیر می‌تواند فرمان ثبت‌شده بفرستد؛ برای فرمان‌هایی که کامپیوتر را تغییر می‌دهند کاربر همچنان کارت تأیید می‌بیند. | همه می‌خوانند، مدیر می‌فرستد |
| **Devices** | آنچه از بررسی‌های قبلی دربارهٔ هر کامپیوتر می‌دانیم (ویندوز، سخت‌افزار، دیسک‌ها، برنامه‌ها، درایورها) و اینکه چقدر قدیمی است. **Read now** دوباره از همان کامپیوتر می‌پرسد. کامپیوترها هیچ‌وقت سر زمان مشخص پرسیده نمی‌شوند. | همه می‌خوانند |
| **Health rules** | بررسی‌های روزانه یا هفتگی که مشکل‌های رایج را پیش از تماس کاربر رفع می‌کنند. [قانون‌های سلامت](/docs/health/) را ببینید. | همه می‌خوانند، مدیر تغییر می‌دهد |
| **Packages** | هر بستهٔ تعمیر و نصب با وضعیت، علائم، پیش‌نیازها، هش‌ها، امضاکننده و اینکه اگر Ready نیست دقیقاً چه چیزی را باید درست کرد. مدیر یک بستهٔ نصب را روی **No approval needed** می‌گذارد. | همه می‌خوانند، مدیر کلید را می‌زند |
| **Helpdesk** | گفتگوهای زنده، موارد ارجاع‌شده، به دست گرفتن گفتگو، تشخیص فقط‌خواندنی. [کار روزانهٔ پشتیبانی](/docs/helpdesk/) را ببینید. | کارشناس پشتیبانی و بالاتر |
| **Approvals** | درخواست‌هایی که منتظر کارشناس پشتیبانی‌اند: حذف نرم‌افزار، بسته‌های حذف، و تعمیرهایی که مدیر «Needs IT approval» زده است. **Approve and run** فوراً اجرا می‌کند؛ **Decline** یادداشتی می‌گیرد که کاربر می‌بیند. | کارشناس پشتیبانی و بالاتر |
| **Lessons** | هر گفتگوی حل‌شده یک درس کوتاه به جا می‌گذارد (کاربر چه گفت، چه امتحان شد، چه چیزی درستش کرد) که بدون هوش مصنوعی نوشته می‌شود. کارشناس ارشد از آن پیش‌نویس مهارت می‌سازد، برای تحلیل نگهش می‌دارد یا کنارش می‌گذارد؛ فقط مهارتی که کارشناس ارشد منتشر کند به عامل می‌رسد. بالای صفحه نشان می‌دهد کدام رفع‌ها بیشترین گفتگوها را حل کرده‌اند. | همه می‌خوانند، کارشناس ارشد تصمیم می‌گیرد |
| **Feature requests** | چیزهایی که کاربران خواسته‌اند و سیستم هنوز نمی‌تواند: New، Planned، Done، Declined. | کارشناس ارشد و بالاتر |
| **Capabilities** | چهار زبانه: **Actions** (کلیدها و سقف‌ها، مدیر تغییر می‌دهد)، **Agent tools**، **Writing a skill**، **Recent runs** (کارشناس ارشد می‌تواند یک تعمیر را برگرداند). | همه می‌خوانند |
| **Skills** | نوشتن پیش‌نویس، بررسی، ارسال، انتشار، بازنشستگی و بازگشت مهارت‌ها. | کارشناس می‌نویسد، کارشناس ارشد منتشر می‌کند |
| **Environment** | سه زبانه: **Targets** (سرورها، سامانه‌های وب، چاپگرها، پوشه‌ها، به‌علاوهٔ **نرم‌افزارهای قابل حذف**، **فهرست درایور** مدل‌های دستگاه و **VPNهای سازمان**)، **Standards** (پسوند DNS، پروکسی، منطقهٔ زمانی، ریشه‌های CA) و **Incidents**. | همه قطعی اعلام می‌کنند، مدیر بقیه را ویرایش می‌کند |
| **Operators** | ساختن حساب محلی، افزودن کاربر دامنه، تغییر نقش، غیرفعال‌کردن حساب، ریست رمز. | مدیر |
| **User manual** | همین راهنما. | همه |

## پیدا کردن صفحه‌ها

همهٔ صفحه‌ها در نوار کناری سمت چپ‌اند و در گروه‌های **Monitor**، **Support**، **Agent setup**، **Administration** (فقط مدیرها) و **Help** آمده‌اند. صفحهٔ فعلی پررنگ است و عددهای قرمز تعداد موارد منتظر را نشان می‌دهند (مثلاً گفتگوهای باز پشتیبانی).

- دکمهٔ بالای نوار کناری آن را به حالت فقط‌آیکن کوچک می‌کند؛ با بردن ماوس روی آیکن نام صفحه دیده می‌شود. داشبورد این انتخاب را روی همین کامپیوتر به خاطر می‌سپارد.
- در پنجرهٔ باریک نوار کناری پنهان است. با دکمهٔ منو در نوار بالا بازش کنید و با **Esc**، دکمهٔ بستن یا کلیک بیرون از آن ببندید.
- نوار بالا نام صفحه، وصل بودن به‌روزرسانی زنده، تعداد کامپیوترهای آنلاین و دکمهٔ تازه‌سازی را نشان می‌دهد.

دکمهٔ حساب در پایین نوار کناری نشان می‌دهد چه کسی وارد شده و نقشش چیست و به حساب‌های محلی اجازهٔ تغییر رمز و خروج می‌دهد. کاربران دامنه رمزشان را در Active Directory عوض می‌کنند.

## اولین راه‌اندازی

اولین بار که API بالا می‌آید حساب `admin` را می‌سازد و رمز یک‌بارمصرفش را در `initial-admin-password.txt` کنار پایگاه داده می‌نویسد (هنگام توسعه در `.local\`، در تولید در `C:\ProgramData\EndpointAgents\ControlPlane\`). وارد شوید، رمز تازه بگذارید و فایل را پاک کنید. حساب‌های شخصی را در صفحهٔ Operators بسازید؛ رمز یک‌بارمصرف هر کدام فقط یک بار نشان داده می‌شود.

## بررسی‌های روزانه

1. **Helpdesk:** اول موارد ارجاع‌شده.
2. **Overview:** وضعیت اتصال Live است و عامل‌های مورد انتظار آنلاین‌اند؟
3. **Packages:** چیزی Not signed، Hash mismatch یا غیر از Ready هست؟
4. **Feature requests:** درخواست‌های تازه برای بررسی.
5. **Capabilities، Recent runs:** تعمیرهای ناموفق یا برگردانده‌شده.

## عیب‌یابی

| نشانه | علت محتمل و کار لازم |
| --- | --- |
| نوار بالا Unavailable یا Reconnecting نشان می‌دهد | اتصال زنده به API قطع است. مطمئن شوید API روشن است و `http://localhost:5052/health/live` جواب 200 می‌دهد. |
| پورت 5052 به‌جای صفحه JSON نشان می‌دهد | طبیعی است. داشبورد روی پورت 3000 است. |
| از کامپیوتر دیگر خطای 403 | طبیعی است. داشبورد و APIهای اپراتور فقط روی خود سرور در دسترس‌اند. |
| بعد از ری‌استارت داشبورد باز نمی‌شود | فرایند Node داشبورد دستی راه‌اندازی می‌شود (`npm.cmd run start` در `src\ControlPlane.Web`) و خودش دوباره بالا نمی‌آید. |
| ورود می‌گوید سرور دامنه در دسترس نیست | با حساب محلی وارد شوید یا بعداً امتحان کنید. برای همین یک مدیر محلی نگه دارید. |
| چند رمز اشتباه پشت‌سرهم | آن نام ۱۵ دقیقه قفل می‌شود. |
| `/health/ready` یا فرمان‌ها خطای 503 می‌دهند | حالت تعمیرات روشن است. مدیر آن را در Overview خاموش می‌کند. |
| یک عامل هیچ‌وقت وصل نمی‌شود | کامپیوتر باید نام واقعی سرور را داشته باشد، نه `localhost`. ثبت‌نام و اینکه دستگاه باطل نشده باشد را بررسی کنید. |
| بسته‌ای نیست یا Invalid است | در Packages بازش کنید و خطی را که با نام فیلد شروع می‌شود بخوانید. بعد از کپی پوشهٔ تغییرکرده روی سرور صفحه را تازه کنید. |
| عامل مهارت یا تغییر SOUL تازه را نمی‌بیند | Hermes فقط چیزی را می‌بیند که در پروفایلش است. `scripts\sync-hermes-profile.ps1 -Check` و بعد بدون `-Check` را اجرا کنید و gateway را دوباره راه بیندازید. |
| کاری در فهرست عامل نیست | خاموش شده یا به سقف ساعتی رسیده است. Capabilities را ببینید. |

برای نصب، پورت‌ها و مسیرها به `docs/control-plane-operations.md` و برای ثبت‌نام دستگاه و راه‌اندازی Hermes به `docs/hermes-support-agent.md` نگاه کنید.
